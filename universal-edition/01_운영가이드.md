# 01. 운영 가이드

## 네 가지 개념

1. **원장(로스터)**: "어떤 루틴을, 어떤 주기로, 무엇을 산출하며 돌리는가"를 적은 단 하나의 표. 이것이 시스템의 원본이고 나머지는 전부 파생물이다.
2. **핸드오프(보고)**: 루틴을 한 번 돌릴 때마다 남기는 고정 양식 보고. 산출물(요약, 초안)과 별개로, "무엇을 했고, 뭘 발견했고, 사람이 뭘 결정해야 하는지"를 7개 항목으로 남긴다. 양식이 고정이라 며칠치를 쌓아 놓고 훑어도 읽힌다.
3. **브리핑(취합)**: 하루의 마지막 프롬프트. 오늘 쌓인 핸드오프를 전부 붙여 넣고 "결정할 것 중심으로 한 장 요약"을 시킨다. 사람은 브리핑만 읽으면 된다.
4. **결정 루프**: 브리핑의 "결정 필요" 항목에 답하면, 그 답을 다음 날 해당 루틴 프롬프트에 한 줄로 넣어 준다. 그리고 결정한 안건은 원장 하단 "처리된 결정" 목록에 적는다. 이 목록이 없으면 같은 질문이 매일 반복된다(실운영에서 가장 자주 터진 사고다).

## 하루 사이클 (10~15분)

```
아침:
 1. 루틴 프롬프트 실행 (P1, P2 … 각 2~3분)
    → 산출물과 핸드오프를 저장소에 날짜별로 붙여넣기
 2. 브리핑 프롬프트 실행 (P3, 오늘 핸드오프 전부 첨부)
    → 브리핑 저장, "결정 필요"에 답하기
 3. 답한 결정을 "처리된 결정" 목록에 한 줄 추가
```

주간 루틴(보고서 초안 등)은 정해진 요일에만 사이클에 끼운다.

## 시작 규모

- **루틴 2개로 시작하라.** 수집형 1개(뉴스·자료 모으기) + 취합형 1개(브리핑). 익숙해지면 분류형(메일·문서 트리아지), 감시형(마감·일정), 생산형(주간 보고서 초안)을 하나씩 추가한다.
- 사람이 실행하는 구조라 4개가 넘으면 부담이 는다. 그 지점이 자동판(Claude Code 에디션)으로 옮길 때다.

## 품질을 지키는 세 가지 습관

1. **0건인 날을 정직하게**: 수집이 없으면 "오늘 없음"으로 기록하게 하라. 채우기 위한 항목은 시스템 신뢰를 갉아먹는다.
2. **핸드오프 양식을 절대 바꾸지 마라**: 양식이 흔들리면 취합 품질이 떨어진다. 바꾸고 싶으면 원장에 날짜와 함께 기록하고 한 번에 바꾼다.
3. **브리핑에 원문을 전재시키지 마라**: 루틴별 1줄 + 결정 필요 항목이면 충분하다. 길어지면 읽지 않게 되고, 읽지 않으면 시스템이 죽는다.
