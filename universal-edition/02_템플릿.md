# 02. 템플릿 (복사해 쓰는 양식)

## A. 원장 (저장소 최상단에 1개만)

```markdown
# 나의 AgentOps 원장

## 루틴 로스터
| 루틴 | 주기 | 실행 프롬프트 | 산출물 |
|---|---|---|---|
| 업계-스카우트 | 매일 아침 | P1 | scout/{날짜}.md |
| 아침-브리핑 | 매일 아침 | P3 | briefs/{날짜}.md |
| 주간-경영브리프 | 매주 화요일 | P4 | exec-briefs/{날짜}.md |

## 변경 이력
> 2026-XX-XX 시스템 시작. 루틴 2개.

## 처리된 결정 (억제 목록)
<!-- 브리핑의 "결정 필요"에 답할 때마다 여기 한 줄 추가. 이 목록에 있는 안건은 다시 묻지 않게 한다. -->
- 2026-XX-XX: (안건 요약) → (결정 내용)
```

## B. 핸드오프 (루틴 실행 1회당 1개)

AI에게 산출물과 함께 이 양식으로 보고를 쓰게 한다. **7개 항목 고정, 추가·삭제 금지.**

```markdown
---
routine: (루틴 이름)
run_at: (날짜와 시각)
status: ok | partial | fail
outputs:
  - (산출물 위치나 제목)
key_findings:
  - (핵심 발견, 3개 이하)
for: [(이 보고를 이어받을 다음 루틴, 없으면 빈칸)]
needs_user:
  - (사람이 결정할 것. "~해 주세요 / ~해도 될까요?" 형태의 완결된 요청문으로. 없으면 빈칸)
---
(본문: 자유 서술, 짧게)
```

- `status`: ok = 정상, partial = 일부만 됨(사유 명기), fail = 실패(사유 명기).
- `needs_user`는 그 항목만 읽어도 판단할 수 있게: 배경 1문장 + 요청 1문장 + (있으면) 권고 1개.

## C. 브리핑 (하루 1개)

```markdown
# 브리핑 {날짜}

한 줄 총평: ok n건 · partial n건 · fail n건 · 미실행 n건

## 결정 필요 (최상단)
1. (핸드오프들의 needs_user 취합. 처리된 결정 목록에 있는 것은 제외)

## 루틴별 핵심 (각 1줄)
- 업계-스카우트: …

## 오늘 우선순위 (3~5개)
1. …

## 시스템 메모
- (양식 위반, 반복 실패 등 운영 특이사항)
```

## D. 저장소 폴더 구조 (로컬 폴더 기준)

```
MyAgentOps/
├── 원장.md
├── scout/          # 루틴별 산출물 폴더
├── handoffs/       # {날짜}_{루틴}.md
├── briefs/         # {날짜}.md
└── exec-briefs/    # 주간 브리프 등
```

Notion을 쓴다면 폴더 대신 페이지 4개(원장 / 산출물 / 핸드오프 / 브리핑)로 동일하게 구성한다.
