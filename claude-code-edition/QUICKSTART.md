# QUICKSTART (레벨 1) — 30분 안에 첫 루틴 돌리기

전제: Claude Pro/Max 구독 + Claude Code. 이 문서는 **레벨 1**이다. 앱 내장 스케줄러로 시작하고, 루틴은 **앱이 열려 있을 때** 실행된다(꺼져 있었으면 다음 실행 때 따라잡는다).

앱을 안 켜도 돌게 하는 건 레벨 2다. 지금은 신경 쓰지 마라. **먼저 매일 아침 읽게 되는 보고 하나를 만드는 게 목표다.**

## 1. 홈 폴더 만들기 (2분)

```bash
mkdir -p ~/AgentOps/{events,handoffs,briefs,dashboard,decisions,proposals}
echo 'export AGENTOPS_HOME="$HOME/AgentOps"' >> ~/.zshrc
```

> **왜 `~/Documents` 아래가 아닌가.** macOS는 `~/Documents`·`~/Desktop`·`~/Downloads`를 별도 권한으로 보호한다. 나중에 OS 스케줄러로 옮길 때(레벨 2) 이 폴더들 안에 있으면 **자동 실행이 파일을 열지 못해 통째로 실패한다.** 처음부터 홈 바로 아래에 두면 그 문제를 통째로 피한다. 이미 다른 곳에 만들었다면 지금 옮기는 게 싸다.

킷의 `templates/`, `bin/`, `hooks/`를 원하는 위치에 복사한다.

## 2. 초기화 인터뷰 (10분)

`skills/agentops-init/SKILL.md`를 `~/.claude/skills/agentops-init/`에 복사한 뒤, Claude Code에서:

```
/agentops-init
```

인터뷰를 거쳐 다음이 생성된다.

- `~/AgentOps/AGENTS.md` — 당신의 루틴 편성표
- `~/AgentOps/PERSONAS.md` — (선택) 직원 페르소나
- 첫 루틴 1~2개 + 아침 브리핑 루틴의 스케줄 등록

**루틴은 두 개까지만 만든다.** 많이 만들수록 좋은 게 아니라, 매일 실제로 읽게 되는 보고가 좋은 것이다.

## 3. 인터뷰 없이 바로 시작하려면 (5분)

`example-pack/`의 daily-scout(관심 주제 일일 수집) + morning-brief(아침 취합)를 그대로 등록해도 된다. `example-pack/README.md` 참조.

## 4. 첫 실행 확인 (5분)

1. 등록한 루틴을 사이드바 "Scheduled"에서 **"Run now"로 1회 수동 실행**한다. 이때 도구 권한을 미리 승인해 두면 이후 자동 실행이 권한 질문에서 멈추지 않는다.
2. `~/AgentOps/handoffs/{오늘}/`에 보고 파일이 생겼는지 확인한다.
3. 다음 날 아침 브리핑에 그 루틴이 나타나면 성공.

## 5. 2주쯤 뒤에 할 것

- 루틴을 3~5개로 늘리고, 서로 필요한 정보를 **핸드오프의 `for:`로 연결**한다. 이때부터 조직처럼 굴러가기 시작한다.
- 사람이 답할 게 생기면 `needs_user`로 올리게 하고, **답한 안건은 `dashboard/decided_needs.json`에 억제 키를 남긴다.** 이걸 안 하면 같은 질문이 매일 반복된다(자세히는 `LEVEL3_결정루프와_관제실.md` 1절).
- 대시보드가 필요해지면 `python3 bin/build_dashboard.py`. 선택 사항이며 없어도 동작한다.
- 이벤트 자동 기록이 필요해지면 `hooks/agent-ops-logger.py`를 `~/.claude/hooks/`에 복사하고 settings.json에 등록한다.

## 자주 묻는 것

- **메일 발송은?** 본인 주소를 하드코딩한 발송 스크립트를 직접 만들어라(킷은 보안상 스크립트를 동봉하지 않는다). 없으면 브리핑은 로컬 파일로 남는다. 어떤 경우에도 **외부 수신자 자동 발송 스크립트를 만들지 마라.** 초안까지가 AI의 몫이고, 보내기는 사람이 누른다.
- **Notion이 없는데?** 전부 로컬 마크다운으로 동작한다. 커넥터는 전부 선택 사항이다.
- **루틴이 며칠 안 돌았는데?** 앱이 꺼져 있었을 가능성이 높다. 브리핑은 이를 "실패"가 아니라 **`미실행`(실행 흔적 없음)과 `중단`(시작했으나 보고 없음)으로 구분**해 보고하도록 설계돼 있다. 둘은 대응이 다르다.
- **보고가 부실한데?** 루틴 프롬프트(SKILL.md)의 [단계]가 너무 추상적일 때 생긴다. "요약하라"보다 "3개 이하로 고르고 각각 왜 골랐는지 한 문장"이 훨씬 낫다.
