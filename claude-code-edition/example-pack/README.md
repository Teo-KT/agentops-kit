# 예시 도메인 팩: 주제 감시 + 아침 브리핑

인터뷰 없이 바로 시작하고 싶은 사람을 위한 최소 구성. 루틴 2개로 프레임워크의 전체 사이클(수집 → 핸드오프 → 취합 → 결정)을 경험한다.

## 구성

| 루틴 | 주기 | 하는 일 |
|---|---|---|
| daily-scout | daily (예: 06:00) | 내가 지정한 주제의 새 소식·자료를 웹에서 수집해 요약, 핸드오프에 보고 |
| morning-brief | daily (예: 06:30) | daily-scout 포함 전 핸드오프를 취합해 한 장 브리핑 |

## 설치 (10분)

1. `daily-scout/SKILL.md`를 열어 `{{주제}}`(예: "우리 업계 규제 동향", "경쟁사 A·B·C 소식")와 `{{AGENTOPS_HOME}}`을 치환한다.
2. Claude Code에서 스케줄로 등록한다: "이 파일 내용으로 매일 06:00 스케줄 태스크 daily-scout를 만들어줘."
3. `../skills/morning-brief/SKILL.md`도 같은 방식으로 06:30에 등록한다.
4. AGENTS.md 로스터에 두 루틴을 등재한다(템플릿의 예시 행이 이 구성 그대로다).
5. daily-scout를 "Run now"로 1회 수동 실행해 권한을 승인하고, `handoffs/{오늘}/daily-scout.md`가 생기는지 확인한다.

## 이 팩이 가르치는 것

- 루틴은 산출물(요약 파일)과 별개로 **핸드오프(보고)**를 남긴다. 브리핑은 산출물이 아니라 보고를 읽는다.
- 수집이 0건인 날은 "오늘 없음"을 정직하게 보고한다. 루틴이 안 돈 날과 구분된다.
- 사람이 개입하는 지점은 브리핑의 "결정 필요" 섹션 하나로 수렴한다.

## 다음 단계

daily-scout의 구조(수집 → 선별 → 요약 → 핸드오프)를 복제하면 메일 트리아지, 마감 감시, 주간 보고서 초안 등 어떤 도메인이든 같은 방식으로 붙는다. `templates/_TEMPLATE_routine.md`에서 시작할 것.
